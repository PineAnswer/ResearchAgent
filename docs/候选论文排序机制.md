# 候选论文排序机制

本文说明论文从检索源返回，到进入人工候选审核列表之间的标准化、去重、评分、重排和持久化流程。评分核心位于 `src/research_agent/application/candidate_ranking.py`，完整链路还涉及检索工具、运行时结果重建、检索审核服务和前端。

## 1. 排序在研究流程中的位置

候选排序不会直接决定最终纳入论文。它负责为 Agent 初筛和用户人工审核提供稳定、有解释的候选顺序：

```text
多组检索词
  → OpenAlex / Crossref / Semantic Scholar / arXiv
  → 单来源字段标准化、年份过滤、场馆评级补充
  → 同一轮多源结果去重合并
  → 第一次 rank_candidates()
  → literature-scout 返回 ScoutReport（ID、三态决定、理由）
  → ResearchRuntimeState 汇总各轮原始结果并再次去重
  → 关联 Agent 决定并再次 rank_candidates()
  → 重建完整 SearchReport
  → CandidateSetSnapshot
  → 服务端分页的人工候选审核
  → 用户选择形成 ScreeningDecision
```

排序分数是辅助信号。人工勾选状态单独保存在 `search_review_selections`，确认审核时才转化为 `ScreeningDecision`。

## 2. 检索输入和来源归一化

### 2.1 查询组合

`search_multi_source()` 接收 `queries: list[str]`：

1. 折叠每条查询中的连续空白；
2. 按不区分大小写的完整字符串去重；
3. 丢弃空查询；
4. 最多保留 6 条查询；
5. 将 `limit_per_source` 裁剪到 1～10。

四个来源并行执行；同一来源内部按查询顺序串行执行，避免同时向同一学术 API 发送突发请求。工具调用抛出异常时会立即重试一次，仍失败则把该“查询 × 来源”写入 `source_status`，其他来源已经返回的结果继续保留。HTTP 层还执行独立的限流和可恢复错误重试策略。

### 2.2 各来源提供的主要排序字段

| 来源 | 论文级影响字段 | 其他字段 |
| --- | --- | --- |
| OpenAlex | `cited_by_count`、原生 `citation_normalized_percentile`、最近年度引用、`fwci`、撤稿状态 | 主题层级、出版类型、场馆、摘要 |
| Crossref | `is-referenced-by-count`、撤稿关系 | DOI、出版类型、场馆、学科、摘要 |
| Semantic Scholar | `citationCount`、`influentialCitationCount` | 学科、出版类型、开放 PDF、场馆、摘要 |
| arXiv | 当前不提供进入影响公式的引用指标 | 分类、预印本元数据、PDF URL |

代码支持 OpenAlex、Semantic Scholar 和 Crossref 三个渠道的近期增长百分位融合；当前网络适配器只有 OpenAlex 从 `counts_by_year` 生成 `recent_citation_velocities`。其他渠道只有在输入已经携带该字段时才参与近期增长融合。

原始引用数不会跨渠道相加，`fwci` 也只保存到候选元数据，当前没有进入综合分公式。

### 2.3 年份过滤与场馆补充

每个来源尽量把年份限制传给上游 API，`prepare_candidates()` 返回前还会再次检查年份：

- 低于 `year_from` 的论文被丢弃；
- 高于 `year_to` 的论文被丢弃；
- 设置了相应边界但论文年份未知时，也会被丢弃。

通过年份检查后，`VenueRankingIndex.enrich_candidate()` 使用本地 SQLite 场馆库补充 CCF、JCR、影响因子和 Nature Portfolio 信息：

1. 优先匹配规范化后的精确别名；
2. 未精确命中时使用 SQLite FTS5 或文本查找召回候选；
3. 通过别名相似度重新排序；
4. 模糊匹配置信度低于 0.82 时放弃评级；
5. 已知论文场馆类型时，只在相同的期刊或会议类型内匹配。

未可靠命中时保持评级为空，并写入解释；系统不会猜测场馆等级。

## 3. 两层候选去重

### 3.1 `search_multi_source` 内部去重

同一次多源工具调用使用以下合并键：

```text
优先：doi:{去除 https://doi.org/ 前缀并转小写的 DOI}
回退：title:{标题转小写、标点折叠为空格后的文本}
```

合并同一键时：

- `sources` 和 `matched_queries` 去重追加；
- 标量字段保留第一条非空值；
- 摘要保留较长版本；
- 作者和学科去重合并；
- 引用数、百分位和增长速度按渠道合并；
- 任一来源标记撤稿，合并结果即视为撤稿；
- `source` 最终显示为多个来源名称的连接。

这个规则是保守的确定性合并。没有 DOI 的论文只有规范化标题完全一致才会合并，不执行语义相似度或作者近似匹配。

### 3.2 跨工具调用和检索轮次去重

`ResearchRuntimeState` 会捕获每次 `search_library` 或 `search_multi_source` 的完整候选结果。在 Scout 完成后，运行时对所有轮次再次去重：

1. 优先取候选的 `paper_id`，为空时取 DOI；
2. OpenAlex URL 和裸 `W...` ID 会统一成裸工作 ID；
3. 仍无标识符时退回到小写、去首尾空白的完整标题；
4. 重复项继续合并来源、查询、作者、学科、指标字典和较长摘要。

这一层对普通 DOI 只使用候选首选标识符，不会同时比较 `paper_id` 和 DOI；无 ID 标题也不折叠内部标点。因此，来源返回的身份字段不一致时仍可能保留少量近重复项。进入个人文献库时还有一套以 DOI、论文 ID、规范化标题和年份构造的保守身份键，属于后续存储去重。

## 4. 排序执行时机

系统通常执行两次全局排序：

1. `search_multi_source()` 对本轮已经合并的候选排序，供 Scout 阅读工具结果；
2. Scout 返回后，运行时汇总全部自动检索轮次，关联三态筛选决定，再对最终候选集排序。

Scout 的轻量 `ScoutReport` 只提供 `candidate_ids`、`screening_decisions` 和 `screening_reasons` 等判断。运行时从已捕获的真实搜索结果中匹配这些 ID，再生成带完整元数据和分数的 `SearchReport`。

如果 Scout 提交了有效真实 ID，最终候选通常只保留与 `candidate_ids` 匹配的论文。当前 Scout 提示要求该列表包含 `include + uncertain`，明确排除项一般不会进入人工候选列表。若候选对象本身带有 `exclude` 决定，排序函数仍支持将其放到三态分组的最后。

人工审核阶段的补充检索有所不同：新查询调用一次 `search_multi_source()`，所以新增批次内部已经排序；`SearchReviewService` 将保留的旧候选放在前面，再追加新检索和手工加入的论文，并按身份键合并。当前实现不会在每次人工 `refine` 后对“旧候选 + 新候选”整体再次调用 `rank_candidates()`。

## 5. 综合分

四个分项的基础权重为：

```text
综合分 = 55% × 相关性
       + 30% × 论文影响程度
       + 10% × 场馆权威性
       +  5% × 候选差异性
```

每个可用分项先限制在 0～100。缺失分项从分母中移除，剩余权重重新归一化：

```text
综合分 = Σ(可用分项 × 对应权重) / Σ(可用权重)
```

相关性和差异性由排序器始终生成；影响程度和场馆权威性可能为空。因此，缺少引用或场馆数据不会自动得到零分。

## 6. 相关性：55%

### 6.1 词元

查询、标题和摘要通过 Unicode `\w+` 提取词元，统一转小写并丢弃长度不超过 1 的词元。相关性使用集合覆盖率，不计算词频、词序、同义词或向量相似度。

### 6.2 单查询和多查询得分

```text
单查询相关性 = 70% × 标题词覆盖率 + 30% × 摘要词覆盖率
总体相关性 = 70% × 最佳单查询相关性 + 30% × 全部查询平均相关性
```

其中覆盖率的分母是当前查询的词元数。总体结果乘以 100 并保留两位小数。

最终运行时排序使用实际执行并记录的全部查询词，因此多轮自动检索的互补查询都会影响最终相关性。空查询或查询没有有效词元时复用候选已有的 `relevance_score`；已有值无效时使用 0，并裁剪到 0～100。

## 7. 论文影响程度：30%

### 7.1 三个影响分项

```text
影响程度 = (65% × P + 20% × Q + 15% × M) / 可用分项权重
```

- `P`：多渠道引用百分位；
- `Q`：Semantic Scholar 高价值引用数在比较集合中的百分位；
- `M`：近期引用速度在比较集合中的多渠道百分位。

任何分项缺失时都从影响分分母移除。

### 7.2 引用百分位融合

```text
P = (50% × OpenAlex
   + 35% × Semantic Scholar
   + 15% × Crossref) / 可用渠道权重
```

OpenAlex 原生 `citation_normalized_percentile` 优先保留。某渠道只有原始引用数时，系统在当前候选集合中计算经验百分位。已有百分位支持 0～1；大于 1 且不超过 100 的值按百分数转换，所有有限值最终裁剪到 0～1。

### 7.3 近期增长

`recent_citation_velocity()` 只读取当前年份之前两个完整年度的数据，并对实际存在的年度记录取平均。随后按候选比较集合转成百分位：

```text
M = (60% × OpenAlex
   + 30% × Semantic Scholar
   + 10% × Crossref) / 可用渠道权重
```

当前 OpenAlex 适配器会填充这个原始速度；Semantic Scholar 和 Crossref 的搜索适配器暂未生成年度速度。

### 7.4 比较集合逐级放宽

当只有原始引用、高价值引用或增长速度时， `_comparison_indices()` 尝试构造可比集合。第一学科、年份和文献类型只有在双方都提供相应字段时才构成限制；缺失字段相当于通配。放宽顺序为：

1. 第一学科相容、同年、文献类型相容，至少 5 条；
2. 第一学科相容、年份相差不超过 1 年、类型相容，至少 5 条；
3. 第一学科和类型相容，不限制年份，至少 5 条；
4. 类型相容、年份相差不超过 1 年，至少 5 条；
5. 类型相容，不限制年份，至少 2 条；
6. 仍不足时使用全部具有该指标的候选。

经验百分位使用中位秩：

```text
(严格低于当前值的数量 + 0.5 × 等于当前值的数量) / 集合大小
```

只有一个可用值时，代码使用保守饱和函数：

```text
1 - exp(-max(0, value) / 20)
```

该回退同时用于原始引用数、高价值引用数和近期速度，避免单条数据直接成为 0 或 100 百分位。

### 7.5 影响数据置信度

置信度单独展示，不进入影响分或综合分：

```text
影响置信度 = 55% × 引用渠道权重覆盖
           + 25% × 影响分项权重覆盖
           + 20% × 渠道一致性
```

- 引用渠道覆盖是当前可用渠道权重之和；
- 影响分项覆盖是 `P/Q/M` 可用权重之和；
- 只有一个引用百分位时，一致性固定为 0.5；
- 至少两个引用百分位时，一致性为 `1 - min(1, 2 × 最大渠道差)`。

渠道百分位最大差达到 0.5 时，一致性降为 0。只有 OpenAlex 的高影响论文仍可获得高影响分，同时显示较低置信度。

## 8. 场馆权威性：10%

当前映射为：

| 评级 | 分数 |
| --- | ---: |
| CCF-A / B / C | 100 / 75 / 55 |
| JCR Q1 / Q2 / Q3 / Q4 | 90 / 70 / 50 / 30 |
| Nature Portfolio | 95 |

同一场馆命中多个体系时，权威性分数取最高值，同时保留全部命中标签作为解释。没有可靠评级时 `authority_score=null`，综合分会重新归一化。

本地场馆库中的影响因子、指标年份和来源链接会保存并显示，但影响因子当前没有进入权威性或综合分公式，避免跨学科直接比较。

## 9. 候选差异性：5%

排序器使用贪心 MMR 风格重排。候选文本由以下字段组成：

- 标题；
- 摘要前 1,000 字；
- 场馆；
- 学科字段。

每轮从尚未排序的论文中计算：

```text
差异性 = 100 × (1 - 与已排序论文的最大 Jaccard 相似度)
```

第一篇候选的差异性固定为 100。后续候选没有任何有效词元时使用中性值 50。差异性只占基础权重的 5%，主要用于打破内容高度相似论文的相邻排序。

这是逐步选择过程：每放入一篇论文，剩余候选的差异性和综合分都会相对当前已排序列表重新计算。

## 10. 三态优先级、撤稿和稳定排序

每次贪心选择使用以下排序键：

1. Agent 决定：`include → uncertain → exclude`；
2. 综合分降序；
3. 相关性降序；
4. 影响程度降序；
5. 年份降序；
6. 标题按不区分大小写的字典序；
7. 原输入位置。

空决定或未知决定在函数中与 `include` 使用同一优先级。正常 Scout 重建路径会为匹配候选补上 `include` 或 `uncertain`；三态优先级只在候选确实携带对应决定时生效。

撤稿候选保留真实 `impact_score` 和各项解释，`composite_score` 最多为 5，并在前端显示“撤稿风险”。这能保留研究史信息，同时把撤稿论文移出默认推荐前列。

## 11. Scout 判断与候选理由

Scout 根据标题和摘要输出三态决定及简短中文理由。运行时用规范化后的真实 `paper_id` 匹配已捕获结果，再把决定写入候选并执行最终排序。

进入人工审核时，`SearchReviewService` 为每篇当前候选生成展示理由：

1. 优先使用 Agent 提供的中文理由；
2. 移除“筛选依据”“核心内容”等前缀；
3. 只取第一句并压缩到最多 64 字；
4. Agent 理由没有中文或为空时，使用摘要第一句；
5. 摘要不足时退回标题和默认人工判断提示。

该理由只用于标题摘要级筛选，不会成为后续 `PaperCard` 证据。

## 12. 人工审核中的顺序与选择

### 12.1 `CandidateSetSnapshot`

`begin_review()` 从最新 `SearchReport` 创建快照：

- 再次按当前年份约束区分可审核候选和 `filtered_candidates`；
- 保留 `SearchReport.candidates` 的现有排序；
- 保存自动检索词、轮次、Agent 三态决定和理由；
- 有 Agent `include` 时默认只勾选这些论文，否则默认勾选全部可审核候选；
- 把初始选择写入 `search_review_selections`。

若搜索确有结果，但全部被年份条件过滤，快照留在 `SEARCHED` 并开放手动恢复；原始过滤候选仍可由用户手动加入。

### 12.2 服务端搜索和分页

```http
GET /api/projects/{project_id}/search-review?page=1&page_size=20&q=...
```

- 默认每页 20 条，允许 1～50 条；
- `q` 最多 300 字；
- 搜索在论文 ID、DOI、标题、场馆、场馆缩写、CCF/JCR 标签和作者中做不区分大小写的子串匹配；
- 搜索只过滤，不改变候选原有顺序；
- 摘要响应最多返回 700 字，并标记是否截断；
- 未达年份要求的候选使用独立分页参数 `filtered_page`。

前端不会按当前页面分数重新排序，因此跨页顺序与保存的 `CandidateSetSnapshot` 一致。

### 12.3 选择持久化与确认

单篇、当前页和全部候选的勾选变化通过以下接口立即写入 SQLite：

```http
PATCH /api/projects/{project_id}/search-review/selection
```

仓储以 `(project_id, paper_id)` 为主键保存布尔选择。服务端拒绝快照中不存在的 ID，并返回跨页的总选择数。

用户执行 `refine` 或 `accept` 时，未勾选论文从下一版候选快照中移除，新搜索结果和手动论文默认加入并选中。`accept` 要求最终候选数至少 1 篇，且不超过后端单次精读容量；当前默认上限为 10，客户端提交的最小值和最大值不会改变该资源约束。

## 13. 前端呈现

候选卡按有值的字段展示：

```text
综合 87  影响 93  相关 84  场馆 100
```

- “综合”悬停内容来自 `ranking_explanation`；
- “影响”悬停展示影响分项、缺失渠道说明和数据置信度；
- “场馆”悬停展示命中的场馆评级；
- CCF、SCI 分区和影响因子作为场馆徽标展示；
- 摘要超过 320 字时，当前页面提供展开与收起；
- Agent 决定显示为“建议保留”“需要判断”或“建议排除”；
- 撤稿候选显示独立风险标签；
- 候选差异性参与综合分，但当前卡片没有单独显示该数值。

用户可以在审核时把论文另存到个人文献库。收藏动作不会改变本次候选选择状态。

## 14. 边界与异常兜底

- 空候选集：`rank_candidates()` 直接返回空列表。
- 空查询：复用已有相关性，缺失时使用 0。
- 非数值、NaN、无穷大：视为不可用；有限的百分位和分数会裁剪到合法范围。
- 负原始计数：裁剪为 0。
- 缺少影响数据：`impact_score=null`，综合分对其他分项重加权。
- 缺少场馆评级：`authority_score=null`，保留未命中解释。
- 单渠道论文：渠道缺失不降低影响分，只降低影响置信度。
- 极端引用数：先转为经验百分位或饱和值，避免原始数量直接支配总分。
- 撤稿：影响指标保留，综合分封顶为 5。
- 多源局部失败：写入 `source_status`，已成功候选继续排序。
- 身份字段不一致：确定性去重可能保留近重复论文，人工审核仍可排除。
- 手工加入但未验证 DOI 的论文：摘要被清空且来源标记为 `user-unverified`，不会把用户输入描述当成研究证据。
- 人工补充后的全局顺序：旧候选在前、新批次在后，新增批次内部保持多源工具排序。

## 16. 当前实现总结

当前排序机制由三层共同完成：多源工具负责同轮结果合并与初排，运行时负责跨自动检索轮次汇总和结合 Scout 判断的终排，人工审核层负责保持顺序、持久化选择并形成最终筛选决定。

综合分强调相关性，以论文级影响百分位辅助，场馆评级和候选差异性只占较小权重。缺失指标通过重新归一化处理，置信度与影响分分离，撤稿状态执行硬性降序。候选顺序为人工判断提供结构化参考，最终纳入仍由用户选择和后端精读容量共同约束。
